# The fusion route, scored as a benchmark provider: 0.09913 on 391 windows

Run `2026-09-08-fusion-rules-temp0-vs-post-june-held-out`, cloned from
`2026-08-22-post-june-held-out-test-clean-pack-cont-`. Started 2026-09-08 21:08 EEST,
completed 2026-09-09 00:35, 391/391 windows, 0 errors, $4.66 of vendor billing.

This is the first time the three-system fusion has been scored by the benchmark rather
than by our own replay harness. Every window was transcribed live: three vendors called
per window, fused by the rules engine, over a supervised HTTP route.

No single window carries the result, and removing any one window does not flip the sign of
any comparison. On `wer-nofillers` the fusion is 0.09866 against Scribe's 0.13390, a
smaller gap (−0.03524) because part of the win against Scribe is filler handling.

On the two training-disjoint cities — the only strata that are not contaminated by our
training set — the ordering holds and widens: **argos 0.08720** against Scribe's 0.13488
(n=40), **orestiada 0.05967** against 0.09481 (n=20).

## The price, stated plainly

**The fusion deletes nearly twice as much as Scribe: 0.01866 against 0.00955, +95%
relative.** It buys the WER win by cutting insertions in half (0.03413 against 0.07526)
while substitutions also fall (0.04634 against 0.05546). That trade is the whole result.

This project's own rule is that a model which lowers WER by omitting hard passages looks
better and is worse. Nothing here decides whether the extra deletions are fillers the
reference also omits or speech that was heard and dropped —
`exp-2026-08-26-chooser-deletion-safety` exists for exactly that question and remains
unrun. **This number does not close it, and must not be quoted as if it had.**

## Seven windows did not actually fuse

`FusionTranscriber` refuses two-system fusion: any component failure returns exact Scribe.
The benchmark cannot see this, because the route answers `{"text": …}` and the window
scores `ok` either way. The traces can, and they say **384 of 391 windows fused (98.2%)**:

- 4 × `timing_invariant` — the fused word timings came out non-monotonic (a word starting
  2–3 s before the previous one ended) and the invariant refused the transcript. **1.0% is
  the first at-scale measurement of that rate**; the 39-response replay that preceded it
  showed 39/39 fusing. The cause was found the same evening by replaying the failing
  windows from cached component responses: pass 1 grouped only *consecutive* tokens sharing
  a Scribe anchor, so an unanchored token between two tokens that share one split the run
  and handed that Scribe word's span out twice, sending the timeline backwards. Fixed in the
  research stack (`eval/live_fusion/providers.py`, commit `cbe9caa4`). **The served route
  still carried the defect during this run** — the port to `src/lib/fusion/timing.ts` in
  `opencouncil-tasks` was still uncommitted when the run ended.
- 3 × `aux_ours_provider_failed` — `TypeError: fetch failed` reaching RunPod, a transient
  network fault, on 3 of 391 calls.

Those seven windows are Scribe rows inside the fusion column. They are part of the headline
number because they are what the system did. Their identity inside the report is **not
recoverable**: traces carry no text by design, and their audio hashes cannot be joined to
benchmark items without the benchmark's own audio bytes. A first-pass attempt to identify
them by hypothesis text failed on a wrong premise — the benchmark's `scribe` column is a
separate ElevenLabs call from August, not our route's Scribe call, so byte-identity was
never expected.

Effect on the headline, as an estimate and not a measurement: at 7/391 windows carrying a
Scribe-shaped error rate instead of a fusion-shaped one, "the fusion when it fuses" is
around 0.0984 rather than 0.09913 — assuming those windows are of average difficulty, which
is unchecked.

## What this number is not

- **It is agreement-with-OpenCouncil, not fidelity-to-audio.** The reference is our own
  published transcript. It records product compatibility. It decides nothing about accuracy.
- **It is not comparable to the previously published fusion numbers.** 0.11154 / 0.11205
  (replay, 391) and 0.11027 (80-window live pilot) were produced with the temperature
  ladder in the GPU decoder, on recorded token streams. This run used `temperature=0.0`
  (shipped 2026-09-08) and live vendor calls. Two variables changed at once; the difference
  between 0.11205 and 0.09913 cannot be attributed to either.
- **It is not a measurement of `temperature=0.0` itself.** No ladder arm ran on these 391
  windows, so nothing here prices the decode change. That price was measured separately and
  in parallel on 60 windows the same evening
  ([the ladder's cost](2026-09-08-temperature-zero-cost.md)): dropping the ladder costs
  **+0.00061 WER** on the shipped `rules_on` arm, while emitting *more* words and *fewer*
  deletions — the ladder was not rescuing speech. The two numbers must not be added or
  confused; this run scores a system that contains that decoder.
- **The pooled column is contaminated.** 105 of the benchmark's 203 meetings are in our
  training set. Read the argos and orestiada strata for model quality; the pool is a
  product-compatibility figure.

## Operational record

The route ran under `fusion-bench-route.service` for the whole run with no restart (same
`MainPID` from 21:05:19 to the end, so the process kept the code it loaded at start), one
`configSha` (`8742d22c1ec0309d`) across all 391 traces, and 391 distinct audio hashes — no
window was served twice. One thing worth recording rather than hiding: the Python fuse core,
which runs as a subprocess per window, was rewritten in place at 22:28:59, mid-run. Its
content is byte-identical to the committed version, so this reads as a touch and not a
change — but the run itself cannot tell "touched" from "changed and reverted". Per-window latency through the public route: **p50 31.2 s, p95
42.0 s, max 49.0 s**, well under Cloudflare's ~100 s origin cut. Total route time 3.38 h at
concurrency 1.

Cost: **$4.66** billed through the benchmark (Scribe $0.22 + Soniox $0.10 per audio hour
over 14.57 hours). The RunPod serverless GPU is billed separately and was **not** measured
here; the `ours` component spent 1.81 h of wall time across 388 calls, which includes queue
and upload, not billable GPU seconds alone.

Procedure and its traps: [`docs/runbooks/fusion-bench-provider.md`](../runbooks/fusion-bench-provider.md).
Configuration freeze taken before the run: `~/.cache/oc-public/fusion-bench-2026-09-08/freeze.json`.

## What it leaves open

1. The deletion question (`exp-2026-08-26-chooser-deletion-safety`) — now with a concrete
   number attached: +0.00911 absolute against Scribe, on the system we would ship.
2. The `timing_invariant` defect: 1.0% of live windows silently degrade to Scribe. It is a
   bug in the timing path, not in any vendor, and it has a measured rate for the first time.
3. Whether the ladder's +0.00061 price holds on windows where the ladder actually *fires*.
   The 60-window measurement found a noise floor of exactly zero — two ladder draws over the
   same 12 windows came out byte-identical — so the nondeterminism is window-dependent, and
   a price measured mostly on quiet windows is weaker than it looks.
